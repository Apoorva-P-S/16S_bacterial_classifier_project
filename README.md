# 16S rRNA Bacterial Genus Classifier

Alignment-free classification of bacterial genera from 16S rRNA gene sequences using k-mer profiling and leakage-free ensemble learning (Random Forest / XGBoost), with integrated SHAP interpretability.

Sequences are sourced from the [SILVA](https://www.arb-silva.de/) reference database. The pipeline cleans raw reference sequences, converts them into fixed-length 6-mer frequency vectors, removes redundant/correlated features, and trains tree-ensemble classifiers under a strain-aware train/validation/test split designed to eliminate data leakage — a well-documented failure mode in genomic machine learning (Whalen et al., 2022, *Nature Reviews Genetics*).

> **Headline result:** 99.02% holdout accuracy (Random Forest and XGBoost), evaluated on a strain-disjoint test set (see [Methodology](#methodology-highlights) below for why that distinction matters).

## Prerequisites

### R (preprocessing: cleaning, k-mer matrix, correlation reduction)

- R ≥ 4.0
- Base R only for the core pipeline (`1_clean_16s_dataset.R` through `3_build_kmer_matrix.R`)
- Optional packages, for nicer/extra diagnostic plots (the pipeline degrades gracefully — with a printed `[SKIPPED]` message — if these aren't installed):
  ```r
  install.packages(c("corrplot", "igraph", "ggplot2", "umap"))
  ```
- **[vsearch](https://github.com/torognes/vsearch)** — external binary, required for the chimera-detection step:
  ```bash
  conda install -c bioconda vsearch
  # or: sudo apt-get install vsearch
  ```

### Python (split manifest, classification, SHAP)

- Python ≥ 3.9
- Install via:
  ```bash
  pip install -r requirements.txt
  ```
  Minimum `requirements.txt` contents:
  ```
  pandas
  numpy
  scikit-learn
  xgboost
  shap
  matplotlib
  joblib
  ```

### Data

- Per-genus FASTA files downloaded from SILVA, placed in `data/data_fasta_small/` (one file per genus, e.g. `Bacteroides.fasta`).

## Quick Start / Usage

Run stages **in this exact order** — the classifier depends on outputs from every prior stage, and the correlation-reduction step specifically depends on the split manifest existing first.

```bash
# 1. Clean raw SILVA sequences (label filtering, length/base filtering,
#    deduplication, nested-sequence removal, chimera detection)
Rscript R/1_clean_16s_dataset.R

# 2. Build the taxonomy metadata table
Rscript R/2_build_taxonomy_table.R

# 3. Build the full (unreduced) k-mer frequency matrix
Rscript R/3_build_kmer_matrix.R

# 4. Generate the train/val/test split manifest (accession-grouped, leakage-aware)
python python/0_make_split_manifest.py

# 4b. (Optional but recommended) Pre-modeling QC: missing values, class imbalance,
#     duplicate/constant/near-zero-variance/sparse/highly-correlated k-mer checks.
#     Purely diagnostic — does not modify any file used downstream.
python python/5_dataset_diagnostics.py

# 5. Visualize correlation structure and reduce redundant k-mer features
#    (fits the reduction on the TRAIN split only — see Methodology below)
Rscript R/visualize_correlation_and_reduce_features_fixed.R

# 6. Train Random Forest + XGBoost, evaluate, run SHAP interpretability
python python/genus_classifier_train_val_test.py
```

Each script has a `CONFIG` block at the top (file paths, hyperparameters, thresholds) — edit those directly rather than passing command-line flags. Every script prints its progress and writes outputs to disk as it goes, so if something looks wrong, the last printed line usually tells you which stage to check first.


**Alternative: Python-only preprocessing** (if you prefer not to use R at all — steps 1–3 and 5 above can be substituted with):
```bash
python python/legacy_preprocessing/0_clean_16s_dataset.py
python python/legacy_preprocessing/1_build_taxonomy_table.py
python python/legacy_preprocessing/2_build_kmer_matrix.py
```
This path does **not** currently include the leakage-fixed, train-only correlation reduction — use the R pipeline above if that matters for your results (it should, for anything you intend to report).

## Methodology Highlights

- **Leakage-aware evaluation:** all splitting uses `GroupShuffleSplit` / `StratifiedGroupKFold`, grouped by NCBI accession/strain ID, so no strain's sequences appear in more than one of train/validation/test. This directly addresses a documented pitfall in genomic ML (Whalen et al., 2022).
- **Single source of truth for the split:** `2.1_make_split_manifest.py` computes the split once; both the R correlation-reduction step and the Python classifier read the same `split` assignment, rather than each independently re-deriving one.
- **Train-only feature selection:** the correlation-based k-mer reduction (|r| > 0.90/0.95 threshold, configurable) is fit using only `split == "train"` rows, then applied to all rows — preventing validation/test data from influencing which features the model ever sees.
- **Interpretability:** SHAP TreeExplainer is integrated directly into the training pipeline for both model architectures (global feature ranking + per-genus directional profiles), not added as a separate post-hoc step.

> **Don't confuse the two correlation checks.** `5_dataset_diagnostics.py`'s `correlated_features()`/`correlation_heatmap()` compute correlation on the **full, pooled dataset** — this is intentional and safe, since that script is purely informational QC and never writes a reduced feature matrix back into the pipeline. The train-only fitting requirement above applies specifically to `visualize_correlation_and_reduce_features_fixed.R`, whose output (`kmer_matrix_reduced.csv`) *does* feed the classifier.

For the full literature grounding and detailed methodology write-up, see the accompanying report documents (literature review, methodology section, technical case study) if included in this repository — e.g. under a `docs/` folder.

## Known Limitations / Future Work

- Evaluated only on curated SILVA reference sequences — no independent, non-SILVA validation cohort yet.
- Closed-set classifier: cannot flag a genus outside its training vocabulary as "unknown."
- Most confusion occurs between *Citrobacter* and *Proteus* (both Enterobacterales) — a hierarchical/two-stage classifier targeting this pair specifically is a candidate improvement.
- Current scope covers 5 genera; scaling to the originally intended ~30-genus task may warrant revisiting whether tree ensembles remain the right architecture at that scale.
